A API Brudam utiliza **tokens JWT Bearer** para autenticação. Toda requisição deve incluir seu token no cabeçalho `Authorization`. Os tokens são gerados diretamente no painel Brudam e expiram após **24 horas**.

## Gerando seu token de API

<Steps>
  <Step title="Faça login no painel Brudam">
    Acesse [app.brudam.com.br](https://app.brudam.com.br) com suas credenciais.
  </Step>
  <Step title="Navegue até as Chaves de API">
    No menu principal, acesse **Configurações → Integrações → Chaves de API**.
  </Step>
  <Step title="Crie uma nova chave">
    Clique em **"Nova Chave de API"** para iniciar o processo de criação.
  </Step>
  <Step title="Configure nome e permissões">
    Dê um nome descritivo à chave (ex: `"Integração ERP"`) e selecione apenas as permissões necessárias para sua integração. Consulte a seção [Permissões de token](#permissoes-de-token) para detalhes.
  </Step>
  <Step title="Copie e guarde o token">
    Após a criação, copie o token gerado imediatamente — **ele só será exibido uma única vez**. Armazene-o em um gerenciador de segredos ou variável de ambiente.
  </Step>
</Steps>

## Usando o token nas requisições

Inclua o token no cabeçalho `Authorization` de todas as suas chamadas, seguindo o formato `Bearer {seu_token}`. Substitua `{seu_token}` pelo token gerado no painel Brudam.

<CodeGroup>
  ```bash cURL
  curl -X GET https://api.brudam.com.br/v1/entregas \
    -H "Authorization: Bearer {seu_token}" \
    -H "Content-Type: application/json"
  ```

  ```python Python
  import requests

  headers = {
      "Authorization": "Bearer {seu_token}",  # substitua pelo seu token real
      "Content-Type": "application/json"
  }

  response = requests.get(
      "https://api.brudam.com.br/v1/entregas",
      headers=headers
  )
  print(response.json())
  ```
</CodeGroup>

## Expiração e renovação

Os tokens expiram **24 horas** após a geração. Quando isso ocorrer, a API retornará **HTTP 401 Unauthorized**. Para retomar o acesso:

1. Acesse **Configurações → Integrações → Chaves de API** no painel Brudam.
2. Gere um novo token para a mesma chave.
3. Atualize o token na sua integração.

Para sistemas automatizados, recomendamos monitorar respostas `401` e implementar uma rotina que gere e substitua o token de forma automática antes do vencimento.

## Revogação de token

Se você suspeitar que um token foi comprometido, revogue-o imediatamente:

1. Acesse **Configurações → Integrações → Chaves de API**.
2. Localize a chave desejada e clique nela.
3. Clique em **"Revogar"** para invalidar o token instantaneamente.

Tokens revogados deixam de funcionar imediatamente. Requisições em andamento que utilizem o token revogado receberão **HTTP 401**.

## Permissões de token

Ao criar um token, você pode restringir seu escopo de acesso. Adote o princípio do menor privilégio: conceda apenas as permissões que sua integração realmente precisa.

| Permissão | Acesso concedido |
|---|---|
| `entregas:read` | Listar e consultar entregas |
| `entregas:write` | Criar e atualizar entregas |
| `cte:read` | Consultar CT-es |
| `cte:write` | Emitir e cancelar CT-es |
| `financeiro:read` | Consultar dados financeiros |
| `rastreamento:read` | Consultar rastreamento |

<Warning>
  **Nunca exponha seu token de API em código client-side** (JavaScript no navegador, aplicativos mobile não protegidos, repositórios públicos). Todas as chamadas à API devem ser feitas a partir do seu servidor backend, onde o token permanece seguro.
</Warning>
